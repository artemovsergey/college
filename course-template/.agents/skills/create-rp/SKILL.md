# Создание рабочей программы

## Когда применять

- новый ПМ или учебная дисциплина;
- нужно пересобрать РП под новый учебный план или ФГОС;
- есть нормативная папка и шаблон, но нет готового документа.

Не применять, если нет ФГОС, учебного плана или шаблона: сначала нужно найти
документы, а не писать правдоподобный текст.

## Вход

| Что | Где искать | Обязательно |
|-----|------------|-------------|
| Метаданные курса | `course.yaml` | да |
| ФГОС специальности | `syllabus/normative/` | да |
| Профстандарт | `syllabus/normative/` | да, если есть в колледже |
| Учебный план | `syllabus/normative/` | да |
| Локальные акты | `syllabus/normative/` | да |
| Шаблон РП | `templates/rp.docx` или `.doc` | да |
| Часы и компетенции | учебный план, `course.yaml` | да |
| Стек и ограничения | `course.yaml` | желательно |

## Граница документа

Сначала определить, что создаётся:

- **РП ПМ** — на весь профессиональный модуль. Внутри — все МДК, практики и
  аттестация. Часы модуля и часы МДК — разные строки.
- **РП УД** — на одну учебную дисциплину.

Нельзя делать РП ПМ только по одному МДК. Если в задании 70 ч МДК 01.03, а
нужна РП ПМ.01, документ всё равно описывает весь модуль; 70 ч — только раздел
МДК 01.03.

## Порядок

1. **Проверить вход.** Прочитать `course.yaml`, `AGENTS.md`,
   `docs/architecture.md`. Убедиться, что известны специальность, квалификация,
   модуль, МДК, группа, курс, семестр, преподаватель и часы.
2. **Инвентаризировать нормативку.** Пройти по `syllabus/normative/`, определить
   тип каждого файла и заполнить `syllabus/normative.yml`:
   ```yaml
   schema: 1
   documents:
     - id: "fgos-09-02-07"
       title: "ФГОС СПО по специальности 09.02.07"
       number: "..."
       date: "..."
       source: "..."
       file: "syllabus/normative/fgos-09.02.07.pdf"
       status: "действующий"
       used_for: ["компетенции", "квалификация", "срок обучения"]
   ```
   Читать документы можно через `pandoc`, `python-docx`, `antiword`,
   `pdftotext`. Если файл не читается, зафиксировать это, а не пересказывать по
   памяти.
3. **Извлечь требования.**
   - ФГОС: специальность, квалификация, ПК/ОК, срок обучения, требования к
     материально-технической базе.
   - Профстандарт: обобщённые трудовые функции, трудовые действия, умения,
     знания.
   - Учебный план: часы модуля, МДК, семестры, курсовая, практика, экзамен.
   - Локальные акты: структура РП, формы контроля, оформление.
   Собрать `syllabus/outcomes.yml` и `syllabus/competency-matrix.md`.
4. **Проверить стек.** Для актуальности примеров можно смотреть официальную
   документацию (Context7, Microsoft Learn), roadmap.sh и вакансии. Всё, что не
   из нормативного документа, помечать как «не нормативно». API и версии не
   выдумывать.
5. **Собрать `syllabus/rp.yml`.** Структура — ниже. Часы и коды компетенций
   берутся из документов, а не из головы.
6. **Написать `syllabus/rp.md`.** Один H1, разделы по шаблону, таблицы для
   компетенций и часов. Академический русский язык, без воды и без копирования
   ФГОС целыми абзацами.
7. **Собрать `syllabus/rp.docx`.** Из `templates/rp.docx` через `docxtpl` или
   `python-docx`. Если в шаблоне нет placeholders, допустима сборка из `rp.md`
   с сохранением структуры; отклонение записать в отчёт.
8. **Проверить и сдать.** Пройти чек-лист, написать `docs/rp-review.md`,
   передать методисту, затем преподавателю.

## Структура `rp.yml`

```yaml
schema: 1

course:
  code: "ПМ.01"
  title: "Разработка модулей программного обеспечения"
  specialty: "09.02.07"
  qualification: "администратор баз данных"
  group: "ИБ-243"
  year: "2026/2027"
  study_year: 3
  semester: 5
  teacher: "Фамилия И.О."
  repo_slug: "mdk0103"

hours:
  module_total: 724
  mdk_total: 70
  theory: 28
  practice: 38
  selfstudy: 4
  course_design: 0
  consultation: 0
  exam: 0

passport:
  scope: "Область применения программы"
  goals: ["Цель программы"]
  tasks:
    experience: ["Иметь практический опыт"]
    know: ["Знать"]
    can: ["Уметь"]

outcomes:
  - code: "ПК 1.1"
    type: "ПК"
    text: "Формулировка результата"
  - code: "ОК 01"
    type: "ОК"
    text: "Формулировка результата"

sections:
  - number: 1
    title: "Разработка мобильных приложений"
    mdk: "МДК 01.03"
    hours: {total: 70, theory: 28, practice: 38, selfstudy: 4}
    outcomes: ["ПК 1.1", "ОК 01"]
    topics:
      - title: "Введение в мобильную разработку"
        hours: 2
        kind: lecture
        content: "Что изучается"
        outcomes: ["ПК 1.1"]

conditions:
  material: ["Оборудование, ПО, стенды"]
  information:
    main: ["Основная литература"]
    additional: ["Дополнительная литература"]
    internet: ["Интернет-ресурсы"]
  organization: ["Организация образовательного процесса"]
  personnel: ["Требования к кадровому обеспечению"]

control:
  - outcome: "ПК 1.1"
    indicator: "Показатель оценки"
    method: "Метод контроля"
```

## Структура `rp.md`

Порядок разделов задаёт шаблон колледжа. Типовой бланк РП ПМ:

1. **Паспорт программы**
   - 1.1 область применения;
   - 1.2 цели и задачи (практический опыт, уметь, знать);
   - 1.3 рекомендуемое количество часов.
2. **Результаты освоения** — таблица ПК/ОК.
3. **Структура и содержание**
   - 3.1 тематический план (коды компетенций, разделы/МДК, часы, аудиторная,
     внеаудиторная, практика);
   - 3.2 содержание по разделам (темы, практики, самостоятельная работа,
     учебная/производственная практика, курсовая).
4. **Условия реализации**
   - 4.1 материально-техническое обеспечение;
   - 4.2 информационное обеспечение;
   - 4.3 организация образовательного процесса;
   - 4.4 кадровое обеспечение.
5. **Контроль и оценка результатов** — ПК/ОК, показатели, методы.

Если шаблон РП УД или ФГОС 4 отличается, следовать шаблону. Расхождение
записать в `docs/rp-review.md`.

## Проверки

- Часы модуля, МДК и семестра не смешаны; `total = theory + practice + selfstudy`
  плюс курсовая, консультации и экзамен, если есть.
- Коды ПК/ОК совпадают с ФГОС и учебным планом; каждый результат покрыт.
- В `rp.md` есть все разделы шаблона, таблицы не пустые.
- В `rp.docx` нет `{{ }}`, `TODO`, `None`, обрезанных строк и разъехавшихся
  таблиц.
- В `normative.yml` у каждого документа есть файл или URL и назначение.
- Нет вымышленных приказов, номеров, API и версий.
- Стек соответствует `course.yaml`; устаревшие API не используются.
- `docs/rp-review.md` объясняет решения и расхождения.

## Запреты

- Не придумывать ФГОС, профстандарт, учебный план и номера приказов.
- Не менять часы и состав модуля без решения преподавателя.
- Не копировать ФГОС абзацами; формулировки — своими словами.
- Не выдавать `rp.docx` без проверки таблиц и колонтитулов.
- Не сдавать документ с `TODO` и заглушками.

## Результат

`syllabus/rp.yml`, `syllabus/rp.md`, `syllabus/rp.docx`, `syllabus/normative.yml`,
`syllabus/outcomes.yml`, `syllabus/competency-matrix.md`, `docs/rp-review.md`.
