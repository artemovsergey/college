# Контракт начального контура

Общие правила для скиллов `init-course-repository`, `create-rp`, `create-ktp`.
Скилл ссылается на этот файл и не повторяет его у себя.

## Источник правды

| Факт | Где живёт | Кто пишет |
|------|-----------|-----------|
| Метаданные, часы, стек | `course.yaml` | `init-course-repository` |
| Рабочая программа | `syllabus/rp.yml`, `syllabus/rp.md` | `create-rp` |
| Календарно-тематический план | `syllabus/ktp.yml`, `syllabus/ktp.md` | `create-ktp` |
| Нормативные документы | `syllabus/normative/`, `syllabus/normative.yml` | `create-rp` |
| Учебные источники | `syllabus/sources.yml` | профильный агент |
| План сборки | `plan.yml` | генерируется, руками не правится |
| Артефакты | `dist/` | сборка, в git не коммитится |

Если факт встречается в двух местах, прав тот файл, который выше в таблице.
`plan.yml` пересобирается из `ktp.yml` и frontmatter, а не наоборот.

## Структура

```text
course-<slug>/
├─ AGENTS.md
├─ README.md
├─ course.yaml
├─ plan.yml
├─ syllabus/
│  ├─ rp.md / rp.yml / rp.docx
│  ├─ ktp.md / ktp.yml / ktp.docx
│  ├─ normative.yml
│  ├─ sources.yml
│  ├─ outcomes.yml
│  ├─ competency-matrix.md
│  └─ normative/
├─ course/chapter-NN/
│  ├─ lecture-NN.md
│  ├─ practice-NN.md
│  ├─ selfwork-NN.md
│  ├─ presentation-NN.md
│  ├─ test-NN.yaml
│  └─ assets/
├─ projects/
├─ templates/
├─ .agents/skills/
├─ .opencode/agents/
└─ .github/workflows/
```

Имена файлов — латиницей, с номером: `chapter-01/lecture-01.md`.
Старые репозитории с `Раздел N` и `Лекция N` не переименовываются без отдельной
задачи.

## Нормативная база

- Нормативные документы лежат в `syllabus/normative/`, реестр — в
  `syllabus/normative.yml`.
- У записи реестра есть `id`, `title`, `number`, `date`, `source`, `file`,
  `status`, `used_for`.
- Нормативное требование берётся только из официального документа. Пересказ,
  статья и видео — не нормативка.
- Нет документа — нет требования. Агент останавливается и пишет, чего не хватает.
- Версия ФГОС, профстандарта и учебного плана фиксируется в реестре.
- Roadmap.sh, вакансии и программы вузов нужны для актуальности стека и
  примеров. В тексте они помечаются как «не нормативно».

## Часы

- `total = theory + practice + selfstudy` плюс, если есть, `course_design`,
  `consultation`, `exam`.
- Не смешивать три уровня: часы модуля, часы МДК и часы семестра. У каждого
  уровня своя строка и своя проверка.
- Занятия по 2 часа, если учебный план не говорит иначе.
- Практика не идёт раньше лекции-опоры.
- В разделе не может быть только лекции без практики.
- Менять часы и состав занятий может только преподаватель; агент фиксирует
  расхождение, а не подгоняет документ.

## Компетенции

- Коды ПК и ОК берутся из ФГОС и учебного плана, не придумываются.
- Каждый результат из `outcomes.yml` привязан хотя бы к одному занятию.
- Матрица `syllabus/competency-matrix.md` показывает, где компетенция
  формируется и где проверяется.
- Если код компетенции в документе и в плане расходится, это blocker.

## DOCX

- Шаблоны колледжа лежат в `templates/rp.docx` и `templates/ktp.docx`.
- Старый `.doc` сначала конвертируется в `.docx` через LibreOffice.
- Сборка — через `docxtpl` или `python-docx`. Если в шаблоне нет placeholders,
  допустима сборка из Markdown с сохранением структуры; отклонение фиксируется
  в отчёте, а не выдаётся за точный бланк.
- Перед сдачей DOCX открывается, таблицы проверяются глазами; дополнительно
  можно конвертировать в PDF и просмотреть страницы.
- В DOCX не должно быть `{{ }}`, `TODO`, `None`, пустых таблиц и обрезанных
  формулировок.

## Имена

- Агент — `<роль>-agent`: `course-architect-agent`, `methodist-agent`.
- Скилл — `<глагол>-<объект>`: `init-course-repository`, `create-rp`,
  `create-ktp`.
- ID занятия — `<раздел>-<l|p|s><номер>`: `1-l1`, `1-p2`, `1-s1`.
- Новые репозитории используют `course.yaml`; старые с `course.yml` не
  переименовываются без отдельной задачи.

## Ворота

| Этап | Кто проверяет | Критерий |
|------|---------------|----------|
| Репозиторий | `course-architect-agent` | структура на месте, `course.yaml` валиден, секретов нет |
| РП | `methodist-agent`, рубрика «РП/КТП» | часы сходятся, компетенции покрыты, разделы шаблона на месте, нет заглушек |
| КТП | `methodist-agent`, рубрика «РП/КТП» | часы семестра сходятся, практика после лекции, нет раздела без практики |
| Материал | `methodist-agent`, рубрика «материал» | структура, факты, код и визуалы соответствуют скиллу |
| Методичка | `methodist-agent`, рубрика «оформление» | титул, содержание, приложения и источники на месте |

После методиста результат смотрит преподаватель. Без его решения нельзя менять
часы, номера и состав занятий.

## Запреты

- Не выдумывать номера ФГОС, приказы, профстандарты, API и версии библиотек.
- Не править `syllabus/normative/**`, `rp.docx`, `ktp.docx` и `plan.yml` руками.
- Не коммитить секреты, токены, пароли, персональные данные и внутренние адреса.
- Не оставлять `TODO`, `None` и заглушки без явной пометки.
- Не выдавать черновик за утверждённый документ.
