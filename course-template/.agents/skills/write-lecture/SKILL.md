# Написать лекцию

## Когда применять

- В `plan.yml` есть занятие `kind: lecture`, а файла лекции ещё нет или он
  в статусе заготовки.
- Нужно переписать существующую лекцию под стандарт курса.
- Не применять для практики, самостоятельной работы и презентации — у них
  свои скиллы.

## Вход

- `plan.yml` — занятие по `id`: тема, часы, пререквизиты, outcomes, `file`,
  `slides`, `planned`.
- `course.yaml` — предмет, специальность, группа, стек и версии.
- `syllabus/outcomes.yml` — формулировки ПК/ОК.
- `syllabus/sources.yml` — уже описанные источники.
- Существующий файл лекции или заготовка — вход для переработки, не источник
  истины.

Если `plan.yml` нет или занятие не найдено — остановись. Если пререквизит
не написан, сначала предупреди преподавателя: лекция может опираться на
материал, которого нет.

## Границы

- Одна лекция = одно занятие из плана, обычно 2 ч.
- Объём: 2 ч — 8–14 тыс. знаков; 4 ч — 14–24 тыс. Жёсткий предел — 35 тыс.
- Лекция не заменяет практику: не добавляй варианты заданий и критерии
  оценки. Она даёт теорию, примеры и вопросы для самопроверки.
- Не меняй в `plan.yml` часы, номер, тему и outcomes. Если тема не совпадает
  с планом — это вопрос преподавателю, а не правка плана.

## Порядок

1. Прочитай `AGENTS.md`, `course.yaml`, занятие в `plan.yml`,
   `syllabus/outcomes.yml` и существующий файл.
2. Собери источники: официальная документация языка и библиотек, затем
   учебник, затем статья. Для TypeScript и React Native — официальные
   руководства и Context7/ms_learn. Спорный факт — два источника.
3. Составь план лекции: 3–6 содержательных разделов, каждый заканчивается
   выводом. Не делай план оглавлением.
4. Напиши лекцию по структуре ниже. В каждом разделе: зачем → определение →
   объяснение → пример → вывод.
5. Проверь код: язык у блока, строки ≤ 80, пример компилируется или явно
   помечен как фрагмент. Вывод консоли — отдельный блок `text`.
6. Проверь схемы: не больше двух на лекцию, каждая с подписью и упоминанием
   в тексте. Если схема не нужна — не рисуй.
7. Дополни `syllabus/sources.yml` тем, что реально использовал.
8. Поставь в frontmatter `planned: false`.
9. Пройди чек-лист ниже и верни отчёт: файл, что изменено, источники,
   результаты проверки, открытые вопросы.

## Структура файла

```markdown
---
id: 1-l1
kind: lecture
number: 1
title: Переменные и функции
hours: 2
prerequisites: []
outcomes: [ПК 1.1, ПК 1.2, ПК 1.5, ОК 01, ОК 02, ОК 09]
sources: [ts-handbook]
file: course/chapter-01/lecture-01.md
presentation: presentations/chapter-01/presentation-01.md
planned: false
---

# Переменные и функции

**Цель лекции:** ...

**Аудитория:** ...

## План лекции

1. ...
2. ...

## 1. ...

### 1.1. ...

...

## Резюме

- ...
- ...
- ...

## Контрольные вопросы

1. ...
...

## Материалы

- ...
```

Требования:

- Один `#` — заголовок лекции.
- `**Цель лекции:**` и `**Аудитория:**` — отдельными строками.
- `## План лекции` — 3–6 пунктов, каждый соответствует содержательному
  разделу.
- Содержательные разделы — `## N. Название`, подразделы — `### N.M.`.
- `## Резюме` — 3–5 тезисов, не копия плана.
- `## Контрольные вопросы` — 5–8 вопросов, минимум два выше уровня знания.
- `## Материалы` — источники и ссылки, которые реально использованы.

## Код

- Блок всегда с языком: `typescript`, `bash`, `json`, `sql`, `text`.
- 10–30 строк на пример; после блока — объяснение, что важно.
- Каждый пример вводит новую мысль, а не повторяет предыдущий.
- Не выдумывай API и версии. Версии — из `course.yaml`; если версия не
  указана, пиши «в актуальной версии» и дай ссылку.
- Вывод консоли — отдельный блок `text`, не комментарий внутри кода.

## Схемы

- Mermaid (`flowchart`, `sequenceDiagram`, `classDiagram`, `stateDiagram-v2`)
  или Excalidraw.
- Не больше двух схем на лекцию.
- У схемы есть подпись и упоминание в тексте: «На схеме 1 видно, что…».
- Схема не дублирует таблицу и не заменяет объяснение.

## Источники

- Порядок: официальная документация → учебник → статья → видео.
- Сомнительный источник — пометь «требует проверки».
- В `syllabus/sources.yml` добавь запись по схеме файла: `id`, `title`,
  `url`, `kind`, `accessed`, что взято.
- Не ссылайся на страницу, которую не открывал.

## Проверка

- [ ] Один `#`, обязательные разделы на месте.
- [ ] Объём в пределах 8–14 тыс. знаков для 2 ч.
- [ ] План лекции не равен оглавлению, разделы заканчиваются выводами.
- [ ] Все outcomes из `plan.yml` раскрыты и проверяемы.
- [ ] У каждого блока кода есть язык, строки ≤ 80.
- [ ] Примеры не противоречат друг другу и стеку из `course.yaml`.
- [ ] Схем не больше двух, у каждой подпись и упоминание.
- [ ] Нет `TODO`, `{{ }}`, заглушек и «очевидно».
- [ ] Источники дополнены, ссылки открываются.
- [ ] `planned: false` выставлен.

## Запреты

- Не выдумывать API, версии, названия библиотек и номера стандартов.
- Не менять часы, номера, темы и outcomes в `plan.yml`.
- Не писать практику, СР или презентации вместо соответствующих скиллов.
- Не оставлять скриншот «как должно быть»; для фактического скриншота —
  отдельный скилл визуалов.
- Не коммитить и не пушить без команды преподавателя.
