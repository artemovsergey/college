# Создание календарно-тематического плана

## Когда применять

- РП уже собрана и принята;
- нужен КТП на семестр для конкретной группы;
- перед `build-course-plan`, когда появляются заготовки занятий.

Не применять, пока нет утверждённой РП: КТП выводится из неё, а не из
представлений агента о том, как «должно быть».

## Вход

| Что | Где искать | Обязательно |
|-----|------------|-------------|
| Утверждённая РП | `syllabus/rp.yml`, `syllabus/rp.md` | да |
| Метаданные курса | `course.yaml` | да |
| Семестр, группа, курс | `course.yaml`, решение преподавателя | да |
| Шаблон КТП | `templates/ktp.docx` или `.doc` | да |
| Учебный план | `syllabus/normative/` | да |
| Отчёт по РП | `docs/rp-review.md` | желательно |

Если РП не принята, остановиться. Если часы в РП и учебном плане расходятся,
зафиксировать расхождение и спросить преподавателя, а не выбирать самому.

## Граница документа

КТП делается на **один МДК и один семестр**, даже если РП описывает весь
профессиональный модуль. Часы модуля в шапке не подставляются вместо часов
МДК.

## Порядок

1. **Проверить РП.** Прочитать `rp.yml`, `rp.md`, `docs/rp-review.md`. Убедиться,
   что есть решение методиста и преподавателя. Если статуса нет — остановиться.
2. **Выделить МДК.** Найти в РП раздел нужного МДК. Выписать часы: всего,
   теория, практика, лабораторные, курсовая, самостоятельная работа.
3. **Проверить арифметику.** `total = theory + practice + lab + course_design +
   selfstudy` (лишнее убрать). Сверить с учебным планом и `course.yaml`.
4. **Собрать шапку КТП.** Учреждение, утверждение, название, специальность,
   группа, курс, семестр, преподаватель, часы, основание (ФГОС и РП), решение
   цикловой комиссии. Данные брать из шаблона и документов, не придумывать.
5. **Распределить занятия.** По умолчанию занятие — 2 часа. Сначала лекции,
   затем практики, затем самостоятельная работа. Практика не идёт раньше
   лекции-опоры. В каждом разделе есть хотя бы одна практика.
6. **Заполнить `syllabus/ktp.yml`.** Схема — ниже. Каждая строка таблицы — одно
   занятие с уникальным `id`.
7. **Написать `syllabus/ktp.md`.** Таблица в порядке шаблона: номер, раздел и
   тема, часы, вид занятия, наглядные пособия и ТСО, домашнее задание и
   литература.
8. **Собрать `syllabus/ktp.docx`.** Из `templates/ktp.docx` через `docxtpl` или
   `python-docx`. Если placeholders нет, собрать из `ktp.md` с сохранением
   структуры и записать отклонение.
9. **Создать заготовки занятий.** Для каждой строки — файл в
   `course/chapter-NN/` с frontmatter. Содержание не писать.
10. **Проверить и сдать.** Чек-лист, `docs/ktp-review.md`, методист, затем
    преподаватель.

## Frontmatter заготовки занятия

```yaml
---
id: "1-l1"
kind: lecture
number: 1
title: "Введение в мобильную разработку"
hours: 2
prerequisites: []
outcomes: ["ПК 1.1", "ОК 01"]
sources: []
file: "course/chapter-01/lecture-01.md"
slides: "course/chapter-01/presentation-01.md"
planned: true
---
```

`planned: true` означает, что материала ещё нет. Снимать флаг будет автор
материала, а не КТП.

## Проверки

- Сумма часов всех строк равна `hours.total`.
- `theory + practice + lab + course_design + selfstudy = total`.
- Число лекций, практик и самостоятельных работ совпадает с часами.
- Каждая практика опирается на лекцию, которая идёт раньше.
- Нет раздела без практики.
- ID уникальны, файлы заготовок существуют, frontmatter парсится.
- В `ktp.md` и `ktp.docx` нет `{{ }}`, `TODO`, пустых строк таблицы.
- Таблицы DOCX не разъехались, шапка на месте.
- `docs/ktp-review.md` объясняет распределение и расхождения.

## Запреты

- Не делать КТП на весь модуль, если нужен один МДК и семестр.
- Не придумывать часы, группы и номера протоколов.
- Не ставить практику раньше лекции-опоры.
- Не оставлять раздел без практики.
- Не писать содержание занятий: это следующий этап.
- Не сдавать КТП без утверждённой РП.

## Результат

`syllabus/ktp.yml`, `syllabus/ktp.md`, `syllabus/ktp.docx`, заготовки занятий в
`course/chapter-NN/`, `docs/ktp-review.md`.
