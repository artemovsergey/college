# Шаблон репозитория предмета

Один предмет или МДК. Markdown и YAML — источник правды; DOCX, PDF, PPTX,
сайт и LMS — производные форматы. Архитектура пайплайна — в
[`docs/architecture.md`](docs/architecture.md), правила работы — в
[`AGENTS.md`](AGENTS.md).

## Быстрый старт

1. **Создать репозиторий из шаблона.** «Use this template» на GitHub или
   скопировать каталог. Имя — по коду предмета (`mdk0103`, `mdk0104_IB`).
2. **Заполнить `course.yaml`**: код, название, специальность, группа, год,
   преподаватель, `repo_slug`, часы и стек.
3. **Положить нормативные документы** в `syllabus/normative/`: ФГОС,
   профстандарт, учебный план, локальные акты. Заполнить `syllabus/normative.yml`.
4. **Собрать РП.** Скилл `create-rp` (агент `course-architect-agent`) делает
   `syllabus/rp.md`, `rp.yml` и `rp.docx`. Проверка — методист, рубрика «РП/КТП».
5. **Собрать КТП.** Скилл `create-ktp` делает `syllabus/ktp.md`, `ktp.yml`,
   `ktp.docx` и заготовки занятий. Проверка — та же рубрика.
6. **Собрать план.** Скилл `build-course-plan` (агент `course-planner-agent`)
   делает `plan.yml` из КТП и frontmatter. Руками `plan.yml` не правится.
7. **Писать материалы** по скиллам `write-lecture`, `create-practice`,
   `build-slides`. Каждый материал проходит методиста.
8. **Собрать методичку** скиллом `assemble-methodichka` (агент
   `formatter-agent`) в `dist/docs/`.

Пока скиллы не созданы, шаги 4–8 выполняются вручную по контракту из
`AGENTS.md` и `docs/architecture.md`.

## Структура

| Путь | Что лежит |
|------|-----------|
| `course.yaml` | метаданные, часы, компетенции, стек |
| `syllabus/rp.*` | рабочая программа: Markdown, YAML, DOCX |
| `syllabus/ktp.*` | календарно-тематический план |
| `syllabus/normative/` | ФГОС, профстандарт, учебный план, локальные акты |
| `syllabus/normative.yml` | реестр нормативных документов |
| `syllabus/sources.yml` | учебные источники для занятий |
| `syllabus/outcomes.yml` | планируемые результаты ПК/ОК |
| `syllabus/competency-matrix.md` | матрица компетенций и занятий |
| `course/chapter-NN/` | лекции, практики, СР, презентации, тесты, `assets/` |
| `projects/` | сквозные проекты и эталонные решения |
| `templates/` | Word-шаблоны РП, КТП и титульного листа |
| `.agents/skills/` | скиллы, переносимые между оболочками |
| `.opencode/agents/` | агенты OpenCode |
| `docs/` | архитектура, отчёты, служебные документы |
| `dist/` | собранные артефакты (в git не попадает) |
| `scripts/shot.mjs` | скриншоты фактического прогона |
| `tools/generate_lecture_pptx.py` | генератор PPTX из лекций |

Новые репозитории используют `course.yaml`. Старые с `course.yml` не
переименовываются без отдельной задачи.

## Требования

- Pandoc 3.1+ и antiword — чтение DOCX/DOC.
- LibreOffice — конвертация и проверка DOCX.
- Python 3.12 с `python-docx`, `python-pptx`, `docxtpl`.
- Node.js с Playwright — скриншоты.
- Опционально: Mermaid CLI, Slidev, Typst — для схем, колод и PDF.

## Команды

```bash
node scripts/shot.mjs --command "dotnet --version"
dotnet test projects/01-intro/tests
```

Автоматическая сборка и QA пока не настроены: проверка идёт по чек-листам
из `AGENTS.md`.

## Правила

- Не выдумывать номера ФГОС, приказы, API и версии. Нет документа — нет
  требования; агент останавливается и говорит, чего не хватает.
- Часы и состав занятий не меняются без решения преподавателя.
- `plan.yml`, `rp.docx`, `ktp.docx` и `syllabus/normative/**` руками не правятся.
- Секреты, токены, персональные данные и внутренние адреса в репозиторий не
  попадают.
- Скриншоты — только фактический прогон, без чужих данных.
- `TODO` и заглушки запрещены; отсутствующий скриншот помечается явно.
