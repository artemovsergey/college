# Архитектура пайплайна учебного курса

Документ описывает, как устроен курс и кто делает его артефакты. Он не заменяет
`AGENTS.md` репозитория: здесь — общая схема, там — правила работы с одним
предметом.

## 1. Главный принцип

Репозиторий с Markdown и YAML — единственный источник правды. Всё остальное —
производные форматы:

- DOCX и PDF — для колледжа и печати;
- PPTX и HTML — для занятий;
- JSON — для LMS;
- сайт — для студентов.

Поэтому выбор «git или CollegeLMS» не является архитектурным: LMS — ещё один
целевой формат экспорта. Содержание правится в Markdown, а не в DOCX или в
редакторе LMS.

## 2. Два контура

| Контур | Где лежит | Что меняется |
|--------|-----------|--------------|
| Репозиторий курса | `course-<slug>/` в git | содержание, часы, РП, КТП, материалы |
| Глобальные инструменты | `~/.config/opencode/` | агенты, скиллы, шаблоны, правила |

Репозиторий курса самодостаточен: его можно открыть без глобальных агентов и
прочитать. Глобальные инструменты — сменная часть: их можно переписать, не
трогая содержание курса.

## 3. Этапы

```text
0. init-course-repository   → репозиторий, course.yaml, AGENTS.md, заготовка CI
1. create-rp               → syllabus/rp.md, rp.yml, rp.docx
2. create-ktp              → syllabus/ktp.md, ktp.yml, ktp.docx
3. build-course-plan       → plan.yml, заготовки занятий
4. материалы               → lecture-NN.md, practice-NN.md, presentation-NN.md
5. assemble-umk    → dist/umk/*.docx, *.pdf
```

Этапы 0–2 — начальный контур. Этапы 3–5 подключаются после того, как РП и КТП
приняты. Сайт, LMS, тесты и анимации — следующие цели, не входят в первый
контур.

### Этап 0. Репозиторий

`init-course-repository` создаёт репозиторий из шаблона: структуру каталогов,
`course.yaml`, `AGENTS.md`, пустые `syllabus/` и `course/`, заготовка CI. Заполняются
код специальности, модуль, группа, курс, семестр, преподаватель и стек.

### Этап 1. Рабочая программа

`create-rp` принимает:

- нормативную папку: ФГОС, профстандарт, учебный план, локальные акты;
- шаблон РП: `РП ПМ` или `РП УД`;
- часы и компетенции из учебного плана;
- стек и ограничения.

Сначала агент проверяет, что документов достаточно. Если ФГОС или учебного
плана нет, он останавливается и перечисляет, чего не хватает. Выдумывать
приказы, номера и часы запрещено.

Исследование (roadmap.sh, вакансии, программы вузов, документация технологий)
нужно для актуальности стека и примеров. Нормативные требования берутся только
из официальных документов; всё остальное помечается как «не нормативно».

Результат: `syllabus/rp.md` (читаемый текст), `syllabus/rp.yml` (структура для
сборки), `syllabus/rp.docx` (по шаблону колледжа), `syllabus/normative.yml`
(реестр источников), `syllabus/outcomes.yml` и матрица ПК/ОК.

### Этап 2. Календарно-тематический план

`create-ktp` принимает утверждённую РП и параметры семестра: группа, курс,
семестр, общее число часов. Результат: `syllabus/ktp.md`, `syllabus/ktp.yml`,
`syllabus/ktp.docx` и заготовки занятий с frontmatter.

Проверки: часы семестра сходятся с РП; теория, практика и самостоятельная работа
распределены; у практики есть лекция-опора; нет раздела без практики; номера
занятий уникальны.

### Этап 3. План для сборки

`build-course-plan` собирает `plan.yml` из `ktp.yml` и frontmatter занятий.
`plan.yml` — производный манифест: он не правится руками. При изменении КТП
меняется `ktp.yml`, затем `plan.yml` пересобирается.

### Этапы 4–5. Материалы и УМК

Материалы пишутся по одному занятию: лекция, практика, самостоятельная работа,
презентация. У каждого — свой скилл и чек-лист. УМК собирается из готовых
материалов, а не пишется заново.

## 4. Артефакты

| Артефакт | Источник | Формат | Кто создаёт |
|----------|----------|--------|-------------|
| Метаданные курса | учебный план, решение преподавателя | `course.yaml` | `init-course-repository` |
| РП | нормативка + шаблон | `syllabus/rp.*` | `create-rp` |
| КТП | РП + семестр | `syllabus/ktp.*` | `create-ktp` |
| Нормативная база | ФГОС, профстандарт, учебный план | `syllabus/normative.*` | `create-rp` |
| Учебные источники | документация, учебники, статьи | `syllabus/sources.yml` | профильный агент |
| План сборки | КТП + frontmatter | `plan.yml` | `build-course-plan` |
| Занятие | план + источники | `course/chapter-NN/*.md` | профильный агент |
| УМК | занятия + шаблон титула | `dist/umk/*` | `assemble-umk` |
| Сайт / LMS | те же данные | HTML / JSON | отдельный экспорт |

## 5. Нормативная база

Нормативные документы лежат в `syllabus/normative/`, реестр — в
`syllabus/normative.yml`. У записи есть идентификатор, название, номер, дата,
источник, файл, статус и назначение.

Правила:

- официальный документ важнее пересказа и статьи;
- у каждого требования — ссылка на документ и место в нём;
- нет документа — нет требования; агент останавливается;
- версия ФГОС и профстандарта фиксируется, чтобы курс не «поплыл» между годами.

## 6. Инструменты

Для начального контура достаточно:

- OpenCode — оболочка и агенты;
- Context7 и Microsoft Learn MCP — документация библиотек и платформы;
- GitHub MCP — репозиторий, issues, Actions;
- Pandoc и antiword — чтение DOCX/DOC;
- LibreOffice — конвертация и проверка DOCX;
- Python 3.12 с `python-docx` и `docxtpl` — сборка DOCX из Word-шаблона.

Дальше подключаются Mermaid/D2/Excalidraw для схем, Slidev/Marp для колод,
Playwright для скриншотов, VHS для терминальных демонстраций. Это этапы 4–5,
не начальный контур.

## 7. Имена

- Агент — `<роль>-agent`: `course-architect-agent`, `methodist-agent`.
- Скилл — `<глагол>-<объект>`: `init-course-repository`, `create-rp`,
  `create-ktp`.
- Файлы — латиницей, с номером: `chapter-01/lecture-01.md`.
- Новые репозитории используют `course.yaml`; старые с `course.yml` не
  переименовываются без отдельной задачи.

## 8. Проверка на реальном курсе

Тестовый вход:

- специальность 09.02.07, квалификация «администратор баз данных»;
- ПМ.01 «Разработка модулей программного обеспечения для компьютерных систем»;
- МДК 01.03 «Разработка мобильных приложений»;
- 28 ч лекций + 38 ч практик + 4 ч самостоятельных = 70 ч.

При двухчасовых занятиях это 14 лекций, 19 практик и 2 самостоятельные работы.
Распределение проверяется по учебному плану, а не назначается агентом.

Граница документа: РП ПМ.01 описывает весь модуль, а 70 ч — только МДК 01.03.
Для первого прогона делаем РП ПМ.01 с разделом МДК 01.03 и КТП на 70 ч. Если
нужна отдельная РП МДК, это другой шаблон и отдельное решение.

Проверки первого прогона: часы модуля и МДК сходятся; 70 = 28 + 38 + 4;
компетенции ПК/ОК покрыты; РП и КТП согласованы; в DOCX нет `{{ }}` и `TODO`;
таблицы не разъехались; методист не имеет blocker и major.

## 9. Что не входит в начальный контур

- лекции, практики, презентации и УМК;
- сайт, LMS и экспорт JSON;
- анимации, видео и интерактивные задания;
- автоматическая проверка кода и сборка всех артефактов.

Эти части проектируются после того, как РП и КТП проходят проверку на тестовом
курсе.
